# CC Phase 4 Matrix — Document C: Revised / Removed Items, With Rationale

**Scope covered:** Categories 29–35

### Category 35 — Reviews, Checkpoints & Project Progress

- **REMOVE** — "Project Health" as a CC concept, including any synthetic Project Health score. Reason (per audit): the issue is architectural, not merely terminology — **progress is not "health."** Observable conditions (completed Tasks, remaining work, Flags, Blockers, Decisions, activity, time constraints) can and should be represented directly as discrete, honest indicators. Compressing them into a single synthetic score would produce exactly the kind of AI-computed proxy judgment the architecture has consistently rejected elsewhere (compare: the Flag/Blocker distinction, the "Progress is explicitly an estimate" principle) — it would substitute a single number for Kurt's authoritative judgment rather than supporting it.

- **REVISE** — Original "Deadline" wording (P4-R502–509, "Hard/Target/Soft/Milestone" typing) was superseded by the **External Cutoff** correction. Reason: Kurt clarified he was specifically referring to dates imposed by external reality (conference portal closing, grant deadline, contract expiration) — not internally chosen goals that a project owner might also consider "hard." The original "Hard Deadline" framing left room for ambiguity between the two. The corrected model uses **External Cutoff** specifically for externally imposed dates, keeping them explicitly distinct from internally chosen goals, target dates, and ordinary Task due dates.

- **Process note (numbering collision, not itself a REVISE/REMOVE item):** IDs P4-R502–509 were reused between the original Deadline-typing table and the later External Cutoff revision — the same pattern already flagged for Categories 3, 4, 20, and 26 in earlier chunks. Only the final External Cutoff wording is authoritative and appears in Document A.
